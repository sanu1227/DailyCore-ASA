# 아사 · 팬메이드 AI

BABYMONSTER 아사의 공개 사진을 사용하는 개인용 팬메이드 AI 대화 앱입니다. 실제 인물이나 소속사의 공식 서비스가 아니며 답변은 AI가 생성합니다. 연인 관계를 전제하지 않고 대화와 일정·생활 관리를 지원합니다.

`RIN.exe`를 실행합니다. Chrome/Edge 없이 별도의 프로그램 창이 열립니다. Electron 실행 환경과 Node가 포함되어 있어 Node를 따로 설치할 필요가 없습니다. `RIN.exe`만 옮기지 말고 `RIN-win32-x64` 폴더 전체를 함께 보관하세요.

## 창과 종료

- 기본 화면: 첫 비주 모니터의 반투명 대화 위젯. 처음 크기는 화면 비율을 따르며 1920×1080 화면에서는 1056×594입니다. 기본 불투명도 64%의 차콜색 둥근 패널을 표시하며 패널 바깥 여백은 완전히 투명합니다. 본문은 20~22px, 굵기 600입니다. 제목·상태·버튼을 하나의 헤더로 정리하고 아사는 밝은 흰색, 사용자는 옅은 하늘색으로 표시하며 글씨 외곽선과 그림자는 제거했습니다. 입력창은 투명한 둥근 테두리이며 직접 종료할 때까지 두 번째 모니터에 유지합니다. 일반 창처럼 다른 창 뒤로 가릴 수 있으며 항상 위에 고정하지 않습니다. 헤더의 이름 영역을 끌어 해당 화면 안에서 이동합니다.
- 위젯 크기: **오른쪽 아래 손잡이**를 끌거나 **⋯ 메뉴의 위젯 크기**에서 가로·세로 슬라이더를 조절합니다. 최소 480×360부터 현재 모니터의 작업 영역까지 바꿀 수 있으며 **기본 크기**로 처음 크기를 복원합니다. 손잡이에 키보드 포커스를 두면 방향키로 20px씩 조절할 수 있습니다. 패널·대화·입력창 폭은 창 크기에 맞추고, 입력창은 아래에 유지하며 대화 기록만 스크롤합니다.
- 배경 투명도: 위젯의 **⋯ → 배경 투명도**에서 0~100%로 조절합니다. 0%는 불투명, 100%는 완전 투명입니다. 글씨·버튼은 그대로 유지하고 패널만 바뀌며 설정은 자동 저장됩니다. **기본값**으로 투명도 36%로 복원할 수 있습니다. 메뉴는 닫기 또는 Escape로 닫습니다.
- 표시 문구: 대기 인사, 빈 대화창의 고정 인사, 기본 추천 대화 버튼, 홈·사진의 장식 대사를 제거했습니다. 직접 주고받은 대화 기록과 답변 중 상태, 기능 설명은 유지합니다.
- 클릭 통과: 패널 안팎의 빈 공간에서는 뒤의 바탕화면이나 창을 클릭할 수 있습니다. 입력창·버튼·대화 내용·스크롤바는 조작할 수 있고, 이동은 헤더의 아사 이름 영역을 사용합니다. 확인 대화상자가 열려 있을 때는 위젯에서 입력을 받습니다.
- 상세 앱: 위젯의 **상세**를 누르면 넓은 별도 창(1180×860)이 열립니다. 왼쪽 메뉴에서 모든 기능을 사용하며 실제 사진과 완만한 사진 이동 효과도 상세 앱에서 표시합니다. **위젯으로**는 상세 앱을 숨기고 기존 위젯을 앞으로 가져옵니다. 창을 반복해서 열어도 새 창을 중복 생성하지 않습니다.
- 상태 보존: 두 창의 위치·크기를 따로 자동 저장합니다. 위젯은 항상 두 번째 모니터 작업 영역 안에 복원하며 한 대만 연결되면 해당 화면을 사용합니다. 두 번째 모니터를 다시 연결하면 위젯이 돌아갑니다. 상세 앱 전환과 숨김 후에도 위젯을 유지합니다. 대화·일정·설정은 같은 로컬 서버를 사용하며 변경 알림과 주기 갱신으로 동기화합니다. 입력 초안은 각 창의 세션에 따로 저장하고 전송 성공 후에만 지웁니다.
- 대화로 일정 등록: `내일 오후 3시 팀플 회의 있어`라고 말합니다. 날짜·시간이 부족하면 임의로 저장하지 않으며, 정확한 시간을 반드시 되묻는 규칙은 없습니다. 원하면 이어서 정보를 덧붙일 수 있습니다. 일정 처리 결과를 포함한 모든 대화 답변은 AI가 작성합니다. 등록 카드에서 확인·수정·취소할 수 있습니다.
- 창 조작: 위젯은 최소화·고정 해제 버튼 없이 종료 버튼만 제공합니다. 상세 앱은 제목 표시줄 최소화·최대화와 일반 창 가장자리 조절을 지원합니다. 투명 위젯은 전용 손잡이·메뉴로 크기를 바꾸며 일반 창 가장자리 조절과 최대화는 사용하지 않습니다.
- X: 위젯에서는 창·트레이·알림과 앱이 시작한 서버를 완전히 종료합니다. 상세 앱은 숨기고 기존 위젯을 다시 보여 줍니다. 모니터 분리나 해상도 변경 시 창을 사용 가능한 화면 안에 맞춥니다.
- 완전히 종료: 위젯의 X, 트레이 메뉴의 **아사 종료** 또는 설정의 **아사 종료**.
- 자동 시작: 설정에서 **Windows 로그인 시 아사 시작하기**를 켜면 두 번째 모니터에 위젯을 띄우고 트레이와 알림 엔진을 시작합니다. 상세 앱은 열지 않으며 작업 중인 창의 포커스를 유지합니다.
- 일반 알림: 비주 모니터의 오른쪽 아래에 최대 480×320의 차콜색 카드를 표시합니다. 사진·분류·제목·본문·버튼을 구분하고 긴 본문은 스크롤해서 읽습니다. 모니터가 한 대면 해당 화면을 사용하며 작은 작업 영역에 맞춰 크기를 줄입니다. 알림이 나타날 때 작업 중인 창의 키보드 포커스를 가져오지 않습니다.
- 표시와 소리: 본문 길이에 따라 12~30초 동안 표시합니다. 마우스를 올리거나 알림에 포커스를 두면 자동 닫힘을 멈춥니다. 연속 카드는 2초 간격을 두고, 일반 알림 소리는 최대 1분에 한 번 재생합니다. 같은 키의 대기 알림은 갱신하며 중복으로 쌓지 않습니다. 등록된 알림 주기와 방해 금지 시간은 설정을 따릅니다.
- 알림 조작: **열기**는 관련 화면으로 이동하고 **닫기**, 오른쪽 위 ×, **Escape**는 현재 알림을 닫습니다. **15분 뒤 다시**는 해당 알림을 저장해 다시 보여 줍니다. 재시작 후에도 유지하며, 방해 금지 중에는 종료 후 다음 검사 때 표시합니다. 이전 안내임을 받은 시각과 함께 표시하고, 완료·삭제되거나 시간이 변경된 개별 일정·수업·루틴은 재알림에서 제외합니다.
- 긴급 마감 팝업과 하루 결산은 기존 전용 창과 동작을 사용하며 비주 모니터 중앙에 표시합니다.
- 데이터 복원: 설정에서 정상 판정을 받은 날짜별 자동 백업을 선택합니다. 복원 직전 현재 DB를 별도 안전 백업으로 보존하고, 복원 실패 시 원래 DB로 되돌립니다.
- 여러 항목이 포함된 오늘 브리핑과 시작 시 마감 확인은 한 카드에 합치지 않고 `현재 순서/전체 개수`를 붙여 한 항목씩 순서대로 표시합니다.
- 공식 채널에서 공개한 실제 사진 4장을 상황별 알림과 각 화면에 사용합니다. 대화에서 사진을 고를 수 있으며, 사진 전체에 CSS 이동·확대 효과를 적용합니다. 원본 얼굴과 표정을 새로 생성하지 않습니다.
- 다시 실행: 이미 켜진 아사 창을 앞으로 가져옵니다.
- `Asa.cmd`로 실행합니다. 기존 `SeoA.cmd`, `Rin.cmd`와 `Open-RinWindow.ps1`도 독립 프로그램을 엽니다.

## 데이터와 Codex

이 PC에서는 기존 프로젝트의 `data/rin.sqlite`를 계속 사용합니다. 개인 DB는 배포 폴더에 복사하지 않습니다. 다른 PC에서는 `%APPDATA%/RIN/data`에 기록을 만듭니다. AI 대화·기억 추출·일정 해석은 설치된 Codex CLI와 ChatGPT 계정 로그인이 필요하며 `gpt-6.1-sol`을 사용합니다. 개발용 Codex 프로젝트의 모델 선택과는 분리되어 있으며 전역 설정을 변경하지 않습니다. CLI를 찾지 못하면 `RIN_CODEX_EXE`에 절대 경로를 지정합니다. 로그인·사용량 오류는 그대로 표시하며 다른 제공자로 전환하지 않습니다. 앱은 Ollama와 OmniRoute를 자동 실행하지 않습니다. 일정·기록 화면은 AI가 없어도 사용할 수 있습니다.

이전 스크립트형 아사 서버가 4317 포트에서 실행 중이면 종료한 뒤 데스크톱 알림 호스트로 전환합니다. 서버가 없으면 포함된 Node로 서비스와 알림·PC 활동 측정을 시작하고, 프로그램 종료 시 자신이 시작한 서비스를 종료합니다. 다른 프로세스가 포트를 사용하면 오류를 표시합니다.

e-Class 로그인은 학교 사이트와 기존 Chrome 확장 프로그램을 사용합니다. 앱의 동기화 버튼은 학교 페이지를 열고 실제 새 동기화 기록이 들어오는지 최대 90초 확인합니다. 확장 프로그램이나 로그인 상태가 없으면 성공으로 표시하지 않습니다. 외부 학교 로그인 이외에 아사 화면을 브라우저로 열지 않습니다.

## 개발 및 검증

```powershell
powershell -NoProfile -File desktop/prepare.ps1
node desktop/build.mjs
node --test
dist/RIN-win32-x64/RIN.exe --smoke-test --smoke-report=C:/path/to/report.json
dist/RIN-win32-x64/RIN.exe --smoke-test --smoke-click-through --smoke-report=C:/path/to/click-through.json
```

Electron 44.4.1은 공식 GitHub 릴리스에서 받고 SHA256을 확인합니다. 빌드는 Electron의 수동 패키징 구조를 사용합니다. `--smoke-test`는 별도의 임시 기록·포트를 사용하며 기존 데이터를 변경하거나 실제 Codex 답변을 생성하지 않습니다.

`--smoke-test --smoke-notifications --smoke-report=C:/path/to/report.json --smoke-screenshot=C:/path/to/notification.png`는 알림 위치·포커스·중복 대기·열기·미루기·자동 닫힘과 좁은 화면을 검사합니다. 기본 화면과 긴 본문·320px 너비의 화면을 저장합니다.

`--smoke-click-through`는 위젯 뒤에 임시 수신 창을 띄우고 Windows 마우스 입력으로 실제 클릭 전달을 검증합니다. 검증 동안 해당 모니터의 마우스를 잠시 사용하며 종료 후 원래 커서 위치로 복원합니다. 구현은 [Electron의 클릭 통과와 마우스 이동 전달](https://www.electronjs.org/docs/latest/tutorial/custom-window-interactions#click-through-windows)을 사용합니다.

화면은 HTML/CSS 기반이지만 자체 Electron 프로세스와 창에서 실행됩니다. Node 권한은 화면에 노출하지 않고, 격리된 preload에서 창 조작·학교 페이지 열기·기록 폴더 열기만 제공합니다. 서명된 설치 프로그램이나 자동 업데이트는 포함하지 않은 로컬 실행용 빌드입니다.

참고: [Electron 수동 배포](https://www.electronjs.org/docs/latest/tutorial/application-distribution), [Electron 보안 가이드](https://www.electronjs.org/docs/latest/tutorial/security).

## 사진과 이전 설치 호환성

- 상세 앱의 기본 사진은 `public/assets/asa/moon.jpg`이며, `MOON·CHOOM·SUPA DUPA LUV`를 선택할 수 있습니다. 작은 아이콘과 알림에는 공식 프로필 `portrait.jpg`를 사용합니다. 공식 사진의 원본 얼굴을 유지합니다.
- 움직임은 CSS로 사진 전체를 천천히 이동·확대하는 효과입니다. 눈 깜박임·립싱크·표정 프레임은 생성하지 않습니다.
- 사진 움직임을 끄거나 운영체제의 동작 줄이기를 켜면 효과를 멈춥니다. 숨겨진 창에서도 움직임을 멈춥니다.
- 기존 대화 기록·일정·사용자 기억은 보존합니다. 전환할 때 기존 대화를 AI 문맥에서 제외하여 이전 캐릭터 설정이 이어지지 않게 합니다.
- 기존 설치와 연결을 유지하려고 실행 파일·DB·Windows 자동 시작 바로가기의 내부 이름은 그대로 둡니다.
- 이전 캐릭터의 녹음 파일은 재생하지 않습니다. 알림은 기존 음량 설정을 따르는 짧은 차임을 사용합니다.
- 파일 목록과 출처: [아사 사진 기록](asa-assets.md).
