# 백서아 개발노트

이 문서는 백서아(기존 RIN)의 개발 과정, 설계 결정, 검증 결과를 시간순으로 기록한다. 기능을 추가하거나 동작을 바꿀 때 같은 날짜 아래에 내용을 추가한다.

## 기록 원칙

- 날짜와 작업 목적을 먼저 적는다.
- 실제로 반영된 변경만 기록한다.
- 중요한 설계 결정과 폐기한 방법의 이유를 남긴다.
- 실행한 테스트, 빌드, 실제 동작 확인 결과를 적는다.
- API 키, 비밀번호, 쿠키 같은 비밀값은 기록하지 않는다.
- 아직 확인하지 않은 항목은 완료처럼 쓰지 않고 `남은 확인`에 적는다.

## 2026-09-09 ~ 2026-09-11 — 캐릭터 설계와 로컬 프로토타입

### 목표

토오사카 린의 성격을 반영하면서 외부 유료 API 없이 개인 PC에서 실행되는 생활 동반 앱을 만든다.

### 개발 내용

- 캐릭터 자료를 정리해 인물 바이블, 대화 예시, 평가 기준과 실행 프롬프트를 작성했다.
- Ollama와 `qwen3:8b`를 프로젝트 전용 런타임으로 구성했다.
- Node HTTP 서버, HTML/CSS 화면, SQLite 저장소로 첫 앱을 만들었다.
- 대화, 이름과 표현 강도 설정, 기억, 시간표, 과제·시험 일정, 생활 루틴, 생활 기록을 구현했다.
- Windows 알림, 트레이, 집중 타이머, 하루 브리핑과 결산을 연결했다.
- 활성 프로그램 이름과 사용 시간만 집계하는 PC 활동 측정을 추가했다. 화면 내용과 키 입력은 읽지 않는다.
- Chrome 확장 프로그램으로 한국공학대학교 e-Class Todo를 가져오는 구조를 만들었다.
- 대화와 일정 데이터는 `data/rin.sqlite`에 저장하고 하루 한 번 백업하도록 했다.

### 설계 결정

- 기본 실행은 무료 로컬 모델로 제한했다.
- 기억은 자동 추출하지 않고 사용자가 직접 편집하도록 했다.
- 일정 변경은 서버가 검증한 결과가 있을 때만 완료했다고 말하도록 했다.
- 성격 원본 문서와 실제 소형 모델용 프롬프트를 분리했다.

### 검증

- 실제 Qwen 대화에서 잡담, 피로, 칭찬, 애정 표현과 등록 기억 참조를 확인했다.
- 초기 자동 검사와 반복 답변 재생성 검사를 통과했다.

## 2026-09-17 ~ 2026-09-18 — 대화 품질 개선

### 문제

로컬 Qwen 답변에 상담사 같은 공감, 사용자 말 재진술, 불필요한 질문, 가짜 동행과 문장 반복이 남았다.

### 개발 내용

- 실행 프롬프트에 상담사식 반응과 관찰하지 않은 행동을 금지하는 규칙을 강화했다.
- 반복 문장과 세 단어 어구, 존댓말, 상투어, 과도한 질문을 점수화했다.
- 점수가 높은 답변은 최대 두 후보를 추가 생성해 가장 자연스러운 답변을 선택하도록 했다.
- `조금 어색해요` 평가를 받은 답변과 직전 사용자 메시지는 기록에 남기되 다음 AI 문맥에서 제외했다.
- 반복 억제와 presence/frequency penalty를 조정했다.

### 비교 결과

- EXAONE 3.5 7.8B도 비교했지만 공감, 조언과 연속 질문이 더 많아 채택하지 않았다.
- 긴 프롬프트만으로는 문제를 해결하지 못했다. 프롬프트, 생성 설정, 출력 검사와 실제 사용자 평가를 함께 사용하기로 했다.

## 2026-09-18 — OmniRoute와 무료 Gemini 연결

### 목표

린의 일상 대화 품질을 높이고, 외부 무료 모델에 문제가 생겨도 기존 로컬 실행을 유지한다.

### 개발 내용

- OmniRoute 3.8.50을 로컬 `127.0.0.1:20128`에서 실행하도록 구성했다.
- Google AI Studio 무료 등급의 Gemini 연결을 추가했다.
- 현재 모델 목록을 다시 가져와 `gemini/gemini-3.5-flash-lite`가 실제로 응답하는지 확인했다.
- 린 대화는 OmniRoute Gemini를 먼저 사용하고 오류, 할당량 제한 또는 빈 응답이면 로컬 `qwen3:8b`로 복구한다.
- RIN 전용 OmniRoute endpoint key를 만들고 Windows 사용자 계정으로 암호화해 `%APPDATA%\Rin\omniroute.key`에 저장했다.
- Gemini 키는 OmniRoute 저장소에만 두고 RIN DB와 Git에는 넣지 않았다.
- 앱 시작 시 OmniRoute를 함께 시작하고 endpoint key를 메모리로 전달하도록 했다.

### 개인정보 결정

- Gemini 사용 시 캐릭터 프롬프트, 이름과 표현 강도, 시간대, 등록 기억, 일정과 최근 메시지가 외부로 전송된다.
- OmniRoute와 RIN 서버는 loopback 주소에서만 수신한다.
- 외부 모델 실패 시 로컬 fallback은 인터넷 없이 동작한다.

### 검증

- 인증 없는 OmniRoute 요청이 HTTP 401로 거부되는 것을 확인했다.
- `gemini-3.5-flash-lite` 연결 테스트가 성공했다.
- 실제 린 프롬프트로 일반 대화와 칭찬 반응을 확인했다.
- 자동 검사 72개를 모두 통과했다.
- `node desktop/build.mjs --app-only` 빌드와 RIN 재시작을 완료했다.
- 저장소에서 Gemini 키 원문이 발견되지 않는지 검사했다.

## 2026-09-18 — 게임 중 알림 화면 보호

### 목표

게임 화면 위에 일상 알림이 나타나 플레이를 방해하지 않도록 한다.

### 개발 내용

- 일반 카드 알림을 실제로 표시하기 직전에 게임 상태를 다시 확인한다.
- 게임이 있는 모니터를 계산하고, 알림은 다른 모니터에만 표시한다.
- 다른 모니터가 없거나 안전한 출력 화면을 판별하지 못하면 해당 알림을 표시하지 않는다.
- 긴급 알림과 하루 결산 팝업에도 같은 화면 선택 및 생략 규칙을 적용했다.
- Electron 알림이 실패했을 때 사용하는 Windows 기본 알림도 게임 중에는 표시하지 않는다.
- 알림을 생략해도 처리 완료로 기록하여 같은 알림이 반복해서 재시도되지 않게 했다.

### 설계 결정

- 사용자가 말한 `2번째 모니터`는 고정된 모니터 번호가 아니라 현재 게임이 없는 모니터로 해석한다.
- 알림을 안전하게 옮길 수 없을 때는 게임 화면에 대신 표시하지 않고 조용히 생략한다.
- 대기열에 있던 알림도 게임 시작 이후 나타날 수 있으므로, 대기열 등록 시점이 아닌 실제 출력 시점의 상태를 기준으로 한다.

### 검증

- 자동 검사 73개를 모두 통과했다.
- 단일 모니터와 화면 위치 판별 실패 시 알림이 생략되는 테스트를 추가했다.
- Windows 기본 알림이 게임 중 생략되는 테스트를 추가했다.
- 긴급 및 결산 팝업 PowerShell 스크립트 문법 검사를 통과했다.
- `node desktop/build.mjs --app-only` 앱 빌드를 완료했다.
- 현재 연결된 모니터 2개를 확인했다. 검증 당시 활성 창은 Chrome이어서 실제 게임 알림은 띄우지 않았다.

### 남은 확인

- 다음 실제 게임 실행 중 일상 알림이 게임이 없는 모니터로 이동하는지 관찰한다.

## 2026-09-18 — 창을 닫아도 백그라운드 유지

### 목표

사용자가 `RIN 종료`를 직접 누르기 전까지 린의 트레이, 알림과 백엔드가 계속 작동하게 한다.

### 개발 내용

- 앱 제목 표시줄의 X 버튼은 창 종료 요청을 만들지 않고 즉시 창만 숨기도록 고정했다.
- Alt+F4와 Windows 창 닫기 요청은 기존 보호 처리로 창만 숨긴다.
- 앱 설정과 트레이 메뉴의 `RIN 종료`만 정상적인 전체 종료 경로로 유지했다.
- Windows 로그인 자동 시작은 `RIN.exe --background`로 유지해 창 없이 트레이와 알림을 시작한다.

### 설계 결정

- 별도 감시 프로그램은 추가하지 않았다. Electron 앱 자체의 트레이 생명주기와 단일 실행 잠금을 사용한다.
- Windows 종료, 작업 관리자 강제 종료, 앱 충돌과 전원 차단은 백그라운드 유지 대상에서 제외한다.

### 검증

- Windows 시작프로그램의 `RIN Background.lnk`가 현재 RIN 실행 파일과 `--background`를 가리키는지 확인했다.
- 창이 숨겨진 상태에서도 RIN 프로세스와 `/api/health`가 유지되는지 확인했다.
- 자동 검사와 앱 빌드를 다시 실행했다.

## 2026-09-18 — 안정성·놓친 알림·AI 상태 개선

### 목표

- 일정 등록·변경·조회에 섞인 사용자 정보도 공통 추출 경로를 거친다. 전공·취향 변경을 일정 변경으로 잘못 해석하던 분기도 수정했다.
- 기억과 성공한 대화 한 쌍을 같은 트랜잭션으로 저장한다. 추출 장애에는 대화를 계속하고, 답변 생성 실패에는 기억도 저장하지 않는다. 자동 추가는 대화 문맥을 유지하고 정정은 이전 문맥을 제외한다. 응답 중 기억 편집은 기존 busy 보호를 따른다.
- 기억 테이블에 출처 컬럼을 추가하고 기존 항목은 수동 기억으로 보존한다. 기억 화면에 ‘대화에서 기억’ 또는 ‘직접 남긴 기억’을 표시하며 기존 추가·수정·삭제를 유지한다.
- 대화 프롬프트·마감·수업·루틴·휴식·게임·자리 비움·일상·결산·미리보기 알림을 정리했다. 구체적인 사실이 있을 때만 짧게 잔소리하며, 잡담이나 취향 소개에는 불필요한 재촉을 하지 않는다. 알림 주기·큐·음량·차임은 유지한다.

### 설계 결정

- 새 의존성 없이 기존 SQLite·공급자 구성을 사용한다. 이전 대화를 소급 분석하지 않고 현재 사용자가 직접 말한 정보만 추출한다. 삭제한 기억이 예전 대화에서 다시 살아나지 않도록 과거 대화는 추출기에 보내지 않는다.

## 2026-10-19 — Codex 전용 대화 연결

### 목표

- 사용자의 요청에 따라 대화·기억 추출·일정 해석을 Codex로 통일한다. 다른 모델로 자동 전환하지 않으며 사용량 부족과 인증 오류를 그대로 알린다.

### 개발 내용

- `app/codex.mjs`에서 설치된 Codex의 app-server에 표준 입출력 JSON-RPC로 연결한다. 기존 ChatGPT 로그인을 사용하며 앱에서 인증 정보를 읽거나 복사하지 않는다. 별도 API 키나 dots 화면 조작은 필요하지 않다.
- Codex 프로세스를 재사용하고 요청마다 임시 대화에 최신 앱 문맥을 전달한다. 동시 요청, 스트리밍, 구조화된 기억·일정 결과, 취소·시간 초과·프로세스 종료·사용 한도 오류를 처리한다.
- OpenAI 공급자와 ChatGPT 로그인을 지정하고 서버가 다른 공급자나 모델로 전환하면 실패로 처리한다. 읽기 전용 실행, 승인 요청 거부, 외부 도구 비활성화를 적용하고 예기치 않은 도구 실행 요청도 거부한다.
- 기존 Gemini·OmniRoute·Qwen 호출과 자동 복구 분기를 제거했다. Electron 및 시작 스크립트에서 OmniRoute·Ollama 자동 실행을 제거하고 실행 중이던 린 전용 Ollama도 종료했다. 별도 수동 설치 스크립트와 모델 파일은 보존했다.
- 설정에 실제 응답 모델, 단계별 성공·오류, 첫 글자·전체 처리 시간을 표시한다. 기억 추출이 대화 모델 표시를 덮어쓰지 않고, 사용량을 받지 못했을 때 0으로 꾸미지 않는다.
- 기존 대화·기억·일정의 검증과 원자적 저장을 유지한다. 일반 대화는 한 번 생성하며 문체 때문에 재생성하지 않는다. Electron 구조 검사에는 가짜 Codex 연결을 주입해 실제 사용량을 소모하지 않는다.

### 설계 결정

- 새 의존성 없이 Codex app-server를 사용한다. 린에서의 사용량은 로그인한 Codex 계정을 따르며 결제는 사용자가 직접 처리한다.
- Codex 모델은 기존 설정을 따르고 낮은 추론 강도를 요청한다. 현재 실행 검증 모델은 `gpt-6-astra`다. 오류 발생 시 다른 모델을 호출하지 않고 재시도 가능한 오류를 표시한다.
- 최근 최대 48메시지와 관련 기억·일정을 전달한다. 과거 ChatGPT·dots 대화는 자동으로 불러오지 않는다. 요청마다 문맥을 다시 구성해 기억 삭제와 정정이 반영되게 한다.
- 전역 Codex 설정을 변경하지 않는다. 도구·권한 제한은 요청과 프로세스에 적용한다. 전역 AGENTS 경로가 메타데이터에 남는 사실만으로 내용 주입 여부를 단정하거나 완전한 전역 지침 격리를 주장하지 않는다.
